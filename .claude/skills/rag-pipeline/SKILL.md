# RAG pipeline conventions

Read before editing anything under `backend/app/ingestion/`, `backend/app/retrieval/`, or
`backend/app/agent/`. These rules exist because the failure modes here are quiet — a broken RAG
system does not crash, it just answers wrong.

## Invariants

1. **Department filtering happens in SQL**, on `document_chunks.department_id`. Never fetch broadly
   and filter in Python. Never trust the caller's claim about which department they belong to —
   derive it from the verified JWT.
2. **No citation, no claim.** Every factual sentence in an answer traces to a chunk id that was
   actually retrieved for that turn. Citations are assembled from the retrieval result, never
   generated by the model from memory.
3. **Empty extraction is a failure, not a success.** A document that produced zero non-empty chunks
   is `failed` with a human-readable reason. It is never `ready`.
4. **Embedding model and dimension are load-bearing.** `text-embedding-3-small`, 1536 dims, is baked
   into the `vector(1536)` column. Changing either requires a migration and a full re-index of every
   document — never a quiet config edit.

## Adding a document parser

1. Add a loader in `ingestion/loaders/` that returns `list[ParsedUnit]`, where each unit carries
   text plus positional metadata (`page`, `sheet`, `slide`, `heading_path`, `row_range`).
   The loader's job is extraction and position, not chunking.
2. Register the MIME type and extension in the loader registry. Both, not just the extension —
   uploads are validated on sniffed type as well.
3. Pick a chunking strategy that matches the shape of the format:
   - prose → recursive splitter, ~800 tokens, 120 overlap, respecting heading boundaries
   - tabular → row groups with the header row **repeated in every chunk**, sheet name in metadata
   - slides → one chunk per slide, title retained
   - structured (JSON) → path-aware flattening grouped by top-level key
4. Add a fixture under `tests/fixtures/` and a test — including a deliberately malformed file.
   A parser without a broken-input test will eventually mark a corrupt document `ready`.
5. Set the low-yield floor if the format can produce near-empty output, so it fails loudly.

## Chunking rules

- Chunk metadata must be sufficient to render a precise citation on its own. If a user cannot tell
  *where in the document* an answer came from, the chunk metadata is incomplete.
- Never split a table row across chunks. Never drop a header.
- Keep `chunk_index` monotonic per document — neighbour expansion at retrieval time depends on it.

## Embedding

- Batch requests (100 inputs per call), retry with exponential backoff, and record token usage.
- Failures are per-batch retryable, not per-document fatal. A transient OpenAI 429 must not mark a
  50-page document `failed`.
- Normalise whitespace before embedding, but never strip content that carries meaning
  (currency symbols, identifiers, units).

## Retrieval

Hybrid, always: dense (pgvector cosine) and keyword (`tsquery`) run in parallel and fuse with
Reciprocal Rank Fusion. Dense-only retrieval loses exact identifiers — invoice numbers, SKUs,
policy codes — which is most of what people actually search company documents for. Do not
"simplify" this to vector-only.

- Filter by `department_id` inside both queries, not after fusion.
- Return chunk id, content, score, and full metadata. The citation is built from this, downstream.
- Retrieval functions return data. They do not format prose and they do not call the LLM.

## Agent nodes (LangGraph)

- State is a typed object in `agent/state.py`. Every node takes state and returns a partial update.
  Nodes do not mutate state in place and do not reach outside it for context.
- One node, one responsibility. Routing does not retrieve. Generation does not grade.
- Every loop has an explicit iteration cap. The grade → rewrite → retrieve loop is capped at 2.
  An uncapped loop in an agent is an outage waiting for an unusual question.
- Prompts live in `agent/prompts.py` as named constants, never inline in node bodies.
- Retrieved content goes into a clearly delimited context block, and the system prompt states that
  instructions appearing inside documents are data to be reported, not commands to follow.
- Every node emits a latency metric and logs its decision with `request_id`. When an answer is
  wrong, the log must show which path the graph took.

## Testing this layer

- Mock the LLM. CI never calls OpenAI.
- Test routing decisions per input class: chitchat, document question, catalogue question,
  summarisation, out of scope.
- Test that a weak retrieval result produces the honest "not found" answer rather than a fabricated
  one. This test protects the core promise of the product.
- Test that citations reference only chunk ids present in that turn's retrieval result.
